# ゲームコンテンツの追加

既存の定義型、登録箇所、フックの呼び出し順を確認する。定義と専用フックは対象のサブモジュールに置き、
既存の C11 定義テーブルから参照する。共通の巨大な `switch` に種類ごとの挙動を足さない。

```c
/* 名前とメンバーは対象モジュールの定義型とフック型に合わせる。 */
const EnemyDef example_enemy = {
    .id = ENEMY_EXAMPLE,
    .spawn = example_spawn,
    .step = example_step,
};
```

- 指示付き初期化子で数値とフックを登録する。ウェーブなど、数値定義だけで表せる場合はテーブルで完結させる。
- 挙動を持つ敵やアビリティは専用ファイルに置き、登録変更を1か所に集約する。
- 生成時に必要な ECS コンポーネントと初期値を全て付与する。参照時は Entity ID の世代を検証する。
- 終了や死亡は破棄予約で表現する。回収はティック確定時の共通処理に任せる。
- 乱数はゲームの RNG 状態を使い、更新は固定 60 Hz のティックで表す。
- 並行作業は別の worktree と専用ファイルで進める。共有する ID、登録表、ウェーブ、ビルド定義は担当を決めて統合する。

## 検証

1. 定義の登録、初期コンポーネント、効果の発動条件と寿命を単体テストで確認する。
2. 同じシード集合と入力条件で変更前後を走らせ、対象に応じて出現数、与ダメージ、撃破時間、取得率などを比較する。
3. 集計に使った試行数、代表値、極端な例を記録する。必要に応じて実画面で視認性とプレイ感を確認する。
